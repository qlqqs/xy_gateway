# 前端重构与冗余清理

## 目标

以当前前端已经表达的业务语义和交互流程为唯一产品锚点，在不修改后端的前提下，完成前端领域模型、状态流转和页面交互的重构，使管理端可以脱离后端实现稳定运行、数据结构一致、核心流程可验证，并清除已不可达或重复的前端代码。

## 背景与已确认事实

- 最近的前端改动引入了多 Key 用户、Key 与分组绑定、分组策略以及供应商调度字段；这些改动是业务模型变化，不是单纯的视觉调整。
- 用户页面当前通过 [`frontend/src/stores/users.ts`](../../../../frontend/src/stores/users.ts) 维护硬编码内存数据，分组页面通过 [`frontend/src/stores/groups.ts`](../../../../frontend/src/stores/groups.ts) 维护本地数据；其他页面部分使用 API，造成同一资源存在两套状态来源。
- 前端已有 `api/`、Pinia、通用表格 composable 和请求反馈工具，应复用这些边界，不再增加第二套 HTTP client 或在组件中直接拼接请求。
- 当前用户交互包含：多 Key 增删、Key 生成/重新生成、Key 分组选择、分组 CRUD、供应商分组选择、模型和供应商筛选/编辑、列表分页与刷新。
- 本任务只负责前端；真实后端接口、数据库、鉴权和运行时路由策略不在本任务内。

## 需求

### R1. 统一前端领域模型

- 为用户、用户 Key、分组、供应商、模型和列表结果定义单一的前端领域契约。
- 内部字段命名、可空值、日期和状态值保持一致；表单草稿、领域实体和未来 API DTO 不再混用。
- 用户 Key 使用实体数组表达，并保留稳定标识、分组关系和状态；旧 `keyGroups` 映射不再支持，当前前端只接受 `UserKey[]`。
- 模型价格保留计费模式，不能在前端提交或转换过程中静默丢失。

### R2. 统一数据与状态流转

- 用户、分组以及依赖它们的供应商/模型选项通过统一的 repository/store 边界访问。
- 当前阶段使用可替换的本地 mock 数据源，不依赖运行中的后端；mock 数据在同一会话内可持久化，页面重新进入后仍保持一致。记录、系统状态和连通性测试仍明确属于 API 依赖页面，不在本地 mock 范围内伪造。
- 所有异步操作具备 loading、错误、空数据和成功反馈；失败不能留下错误的 loading 或半更新状态。
- 列表筛选、分页、刷新、创建、编辑、删除和关联变更在同一状态源上生效。

### R3. 跑通现有业务交互

- 用户 Key 的添加、删除、生成、重新生成、去重和分组绑定可完整完成。
- 分组的创建、编辑、删除、协议选择、模型白名单、倍率和启停状态可完整完成；删除时对关联引用给出明确的前端行为。
- 供应商表单中的分组、可用模型、并发、负载因子、优先级、状态和备注字段可正确往返于领域状态。
- 模型表单中的路由、上游、计费模式和价格字段可正确往返于领域状态。
- 仪表盘、余额、记录和管理列表不会因为各自维护同一资源的副本而出现明显的前端数据矛盾。

### R4. 清理冗余代码

- 依据实际引用和路由可达性清理用户/分组旧实现、重复类型、重复请求路径和不可达组件。
- 清理前端已删除功能留下的孤立 API、store、组件和资源；不修改后端对应接口。
- 本任务不承诺旧前端模块的外部调用兼容性；确认无引用或已从产品流程删除的接口、类型和组件直接移除，不保留迁移别名或旧字段适配层。

### R5. 质量与范围

- 遵守 `.trellis/spec/frontend/`、`AGENTS.md` 和现有 Vue/TypeScript 工程规范。
- 只修改 `frontend/` 以及本任务必要的 Trellis 任务产物；不修改 `src/`、数据库、部署配置或后端测试。
- 为新的领域转换、repository/store 行为和关键交互补充最小 Vitest 覆盖，不追求全量端到端测试。

## 验收标准

- [x] 用户和分组页面不再依赖硬编码演示数组；通过统一 mock repository/store 完成完整 CRUD 和关联操作。
- [x] 同一实体在不同页面只有一个状态来源，刷新或重新进入页面后数据不互相覆盖。
- [x] 多 Key、Key 分组、分组策略、供应商配置和模型计费字段在新增/编辑流程中不丢失、不产生未定义值。
- [x] 现有路由可正常加载；不可达的孤立前端模块已删除或有明确保留理由。
- [x] `vue-tsc` 构建通过，核心新增逻辑有最小单元测试，且测试不依赖运行中的后端。
- [x] 改动范围只包含前端和必要的 Trellis 任务文件，工作区没有生成物、数据库或 IDE 配置被纳入改动。

## 明确不做

- 不实现或修改后端用户 Key、分组、供应商调度、鉴权、计费和路由逻辑。
- 不进行与当前交互无关的视觉重设计，不新增产品功能，不照搬其他项目的完整领域模型。
- 不在本任务中提交或推送 Git；完成后只保留 `rebuild` 分支上的工作区改动，等待用户审阅。

## 风险与延后事项

- mock repository 的字段和行为必须保持与当前前端语义一致，但不能伪装成后端已经支持的运行时能力；未来接入后端时直接替换 repository 实现，届时按新的 API 契约重写 DTO，不恢复旧 `keyGroups` 或已删除 API 的兼容层。
- Key 的真实存储和展示安全策略属于后端集成阶段；本任务只保持当前页面的显示/遮罩交互，不扩展敏感信息能力。
- `frontend/public/data_viewer` 是构建输入和独立子项目，清理时不能误删其运行所需资源；ESLint 应通过配置排除生成内容，而不是修改生成文件。
