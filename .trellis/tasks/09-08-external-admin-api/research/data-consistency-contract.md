# 本期数据一致性边界

## 状态

- 日期：2026-09-08。
- 本文件只保留本任务最终接受的简单一致性语义。
- 早期调研中关于 `revision`、账务幂等表、软删除、审计事务和复杂锁协调的内容不属于本期方案；如需这些能力，必须另立任务。

## Admin Key

- 唯一配置项是 `config.name = admin_api_key`，明文 value 只有一个有效值。
- 生成/删除是普通数据库写入；并发时最后成功提交的值有效。
- 鉴权每次直接读取数据库，不使用 `configService` 的永久缓存。
- 不增加版本号、双 Key、候选状态、应用锁、持久幂等或跨进程协调协议。
- 生成响应丢失时，调用方使用 Root/管理员 Bearer 重新生成；不尝试用旧值重放。

## 用户 Key 单项操作

- 单项 API 按 `(user_id, key_id)` 定位目标行，不能先读取整组再整体替换。
- 创建、修改和删除只影响目标 Key；修改不清空 `quota_used`、`last_used_at` 等运行字段。
- 同一 Key 的并发修改采用最后写入语义。
- 旧 `PUT /user/:id/keys.json` 仍是整组替换；页面持有陈旧数组时可能覆盖外部单项 API 的变化。
- 不加 `user.key_revision`、`If-Match`、自动合并、冲突提示或用户级锁。

## 余额和其他既有写操作

- 外部 Admin API 复用现有余额、记录和资源写入逻辑，不在本任务中新增统一幂等层或重做事务边界。
- 外部调用方看到的成功、失败、重复和未知结果语义与现有管理员入口一致。
- 结果未知时不得盲目重试有副作用的写请求；需要更强保证时另行设计持久幂等。
- 本任务不因引入外部入口而修改余额单位、充值记录、结算、删除或历史引用语义。

## 验证范围

- API 测试通过既有 HTTP helper 验证外部路径和业务结果，不直接依赖内部映射字符串完成成功断言。
- 单 Key 测试比较目标行与兄弟 Key 的前后状态，验证没有整组副作用。
- Admin Key 测试验证旧值失效、最终值唯一和缓存不滞留。
- 不运行或设计 D1/Workers 专项并发保证；Node SQLite/MySQL 是本期范围。
