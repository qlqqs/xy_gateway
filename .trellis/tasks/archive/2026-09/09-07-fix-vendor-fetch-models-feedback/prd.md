# 修复供应商自动获取模型无反馈

## Goal

修复新增和编辑供应商时“自动获取模型”请求成功后界面无可见变化的问题，让用户能立即看到并选择获取到的模型。

## Background

- `frontend/src/views/Vendor/DialogCreate.vue` 与 `DialogEdit.vue` 在请求成功后只更新 `fetchedModels`，候选项位于默认关闭的模型下拉框中。
- 成功路径没有提示；用户不再次点击模型选择框时，无法判断按钮是否生效。
- 失败和空列表已有明确文字反馈，后端 `POST /vendor/models/fetch.json` 及前端 repository/store 调用链已经存在。
- 既有产品约定是“获取结果可直接选择”，不是自动把全部上游模型写入供应商配置。

## Requirements

- 新增和编辑供应商弹窗必须采用一致的自动获取模型交互。
- 点击按钮后保留现有加载状态，并使用表单中的 API 地址、协议和认证凭证请求模型列表。
- 获取到非空模型列表后，立即展开模型候选下拉框，并显示获取数量与选择提示。
- 获取结果仅作为候选项，不自动修改用户已选择的模型。
- 空列表和请求失败时保留现有错误反馈，且不能遗留成功状态或打开空下拉框。
- 每次打开弹窗或重新发起请求时清理上一次的临时成功反馈。
- 补充新增和编辑两条成功路径的组件回归测试，覆盖按钮调用、可见反馈和候选列表展开状态。

## Acceptance Criteria

- [x] 新增供应商弹窗成功获取两个模型后，显示“已获取 2 个模型，请从下拉列表选择。”并展开候选列表。
- [x] 编辑供应商弹窗具有相同成功行为。
- [x] 成功获取不会自动追加或覆盖 `formState.models`，只有用户选择后才进入保存载荷。
- [x] 空列表与失败仍显示原有错误信息，按钮结束后退出 loading 状态。
- [x] `frontend/src/views/Vendor/Dialog.test.ts` 聚焦测试、前端类型检查、相关 lint 和前端构建通过。

## Out of Scope

- 不修改供应商模型获取后端接口或上游协议解析。
- 不自动选择全部返回模型。
- 不测试 D1、Worker 或 MySQL。
