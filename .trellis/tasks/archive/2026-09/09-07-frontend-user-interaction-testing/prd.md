# 前端用户操作按键与使用测试

## 目标与用户价值

以管理员在前端实际使用产品的路径为中心，验证可点击控件、表单提交、确认弹窗、路由跳转、请求反馈和失败恢复。测试应能稳定重现用户可见问题，并在确认问题后自动完成最小修复，避免只验证内部函数而漏掉跨组件交互。

## 背景与已确认事实

- 前端技术栈为 Vue 3、TypeScript、Ant Design Vue、Pinia、Vue Router、Vitest + jsdom；测试文件与被测组件同目录。
- 在本任务开始时前端有 12 个测试文件、52 个用例，已经覆盖登录、Key 编辑、余额调整、模型上游以及 repository/store/composable 基础行为；本任务新增 10 个页面/布局测试文件后，当前为 22 个文件、96 个用例。
- 当前仍缺少页面级用户操作覆盖的主要区域：Model 主列表及表单、Record 详情、AdvancedSettings、Dashboard；Group、Vendor、Record 列表、Header、Sidebar 和余额列表筛选/调整入口已纳入本任务。
- 交互入口和实现位置已由代码核对：
  - `views/Group/List.vue:20-58,176-271`：搜索/重置、新建/编辑/删除及确认弹窗。
  - `views/Vendor/List.vue:34-90,151-201`：搜索/重置、新建/编辑/测试/删除及缓存刷新。
  - `views/Vendor/DialogCreate.vue:22-26,121-263`、`DialogEdit.vue:21-25,123-280`：协议切换、模型获取、保存/取消、失败反馈。
  - `views/Model/List.vue:30-124,213-289`、`DialogForm.vue:19-266`、`UpstreamConfig.vue:24-224`：模型 CRUD、测试、上游增删改和表单保存。
  - `views/Record/List.vue:48-145`、`Record/Detail.vue:11-132,350-434`：筛选、自动刷新、详情导航、复制/下载/删除/展开。
  - `views/AdvancedSettings.vue:158-222,324-469`：保存/取消、更新检查、记录清理和开关状态。
  - `views/Dashboard.vue:16-29,255-350`：刷新、自动刷新、统计加载和卸载清理。
  - `components/layout/AppHeader.vue:4-108`、`AppSidebar.vue:52-143`：退出、主题、开发者入口、导航和折叠。
  - `views/Balance/components/UserBalanceTable.vue:15-59,101-105`、`RechargeRecordsTable.vue:26-108`：列表筛选、分页和余额调整入口。
- 项目规范要求 API 经过 `api/` 或 repository/store 边界，异步按钮必须有 loading、成功反馈和失败恢复，破坏性操作必须先确认，图标按钮必须有可访问名称。
- 当前工作区有大量既有未提交改动；本任务不得覆盖、回滚或提交这些改动，也不得把 `dist/`、数据库、日志、env 或 IDE 文件纳入任务产物。

## 范围内

1. 为上述页面和关键子组件补充基于用户动作的 Vitest + Vue Test Utils 测试：点击、输入、选择、确认、取消、路由、事件和请求参数均通过可观察行为断言。
2. 覆盖每类高风险动作至少一条成功路径和一条失败/恢复路径；删除、退出、跳转等副作用必须验证确认或前置条件。
3. 覆盖列表搜索/重置/分页/刷新、表单 CRUD、模型获取/连通性测试、Key/余额/记录等数据写入或删除动作，以及 loading/disabled/错误提示。
4. 复用现有 mock、repository、store 和轻量 Ant Design stubs；测试不得依赖真实后端、真实供应商或外部网络。
5. 对测试稳定复现且期望行为明确的前端产品问题做最小修复；每个修复先运行原问题最短复现，再运行对应回归测试。若问题属于后端或契约范围，记录证据并单独说明，不用测试替身掩盖。
6. 按分层门禁执行：先最小受影响测试，再前端全量测试、严格类型、lint 和官方构建；最后一次全量门禁只在所有已发现问题完成回归后执行。

## 范围外

- 不引入浏览器 E2E/Playwright 基础设施，不做压力、视觉快照或真实供应商联调；如后续需要，另开任务。
- 不重写现有测试框架，不删除与本任务无关的测试。
- 不修改后端业务逻辑，除非后续用户明确扩大范围；后端问题只保留可复现证据。
- 不执行 `git commit`、`git push` 或破坏性清理。

## 验收标准

- [x] 每个已纳入页面的高风险用户动作都有独立、可读的组件测试入口，且成功、失败/恢复、确认或禁用条件有可观察断言；延期页面已明确列出。
- [x] 测试覆盖矩阵与实际文件/用例一一对应，明确延期项和原因。
- [x] 每个确认缺陷都有最短复现、修复范围和回归命令；没有通过放宽断言或修改 fixture 隐藏问题。
- [x] 前端全量 Vitest、`vue-tsc -b`、`eslint src` 和官方 `npm run build` 全部通过。
- [x] 测试执行不访问真实供应商，不产生需提交的生成物，并保留既有工作区改动。
